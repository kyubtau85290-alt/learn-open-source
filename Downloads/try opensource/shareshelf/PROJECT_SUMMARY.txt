📊 DATABASE SCHEMAS
===============================================

User
  - name, email (unique), password (hashed)
  - location, trustScore (0-100)
  - avatar, bio, phone
  - completedSwaps, overdueCount

Item
  - ownerId (ref User), title, description
  - category, images[], availability
  - depositAmount, location, condition

BorrowRequest
  - itemId, borrowerId, ownerId
  - status (requested→approved→picked_up→returned)
  - dueDate, returnedAt, depositState
  - requestedAt, approvedAt, pickedUpAt

Review
  - borrowRequestId, reviewerId, revieweeId
  - rating (1-5), comment, reviewType

===============================================
🔄 STATE MACHINE FOR BORROW REQUESTS
===============================================

TRANSITIONS:
requested  → approved (owner) | rejected (owner)
approved   → picked_up | rejected
picked_up  → returned | overdue
overdue    → returned
returned   ✓ (final state)

All invalid transitions are blocked with clear error messages!

📧 EMAIL NOTIFICATIONS SETUP
===============================================

WITHOUT CONFIG (Default - Logs to Console):
✅ Works out of the box
✅ Perfect for development
✅ Shows emails in terminal

WITH GMAIL CONFIG:
1. Enable 2FA on Gmail
2. Create "App Password"
3. Add to backend/.env:
   EMAIL_USER=your_email@gmail.com
   EMAIL_PASS=your_16_char_password

WITH CLOUDINARY CONFIG (Optional):
1. Sign up at cloudinary.com
2. Add credentials to backend/.env:
   CLOUDINARY_NAME=your_name
   CLOUDINARY_API_KEY=your_key
   CLOUDINARY_API_SECRET=your_secret
